**J'anticipe.** Si le RPO du serveur de fichiers est de **4 heures**, une sauvegarde nocturne suffit-elle ? Pourquoi ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

**Non.** Une sauvegarde nocturne laisse jusqu'à **24 heures** de données non protégées. Pour un RPO de 4 heures, il faut au minimum une sauvegarde **toutes les 4 heures** (ou une réplication, avec une sauvegarde distincte contre les erreurs).

Exemple de réponse (autres valeurs acceptées si justifiées) : fichiers : haute, RTO 4 h, RPO 4 h (période fiscale) ; messagerie : haute, RTO 4 h, RPO 1 h ; comptabilité : haute, RTO 4 h, RPO 4 h ; Internet : haute, RTO 2 h, sans RPO (pas de données).

</details>

## Partie B – Dimensionner la stratégie (≈ 35 min)

**But :** comparer trois stratégies sur le **stockage** et la **restauration**.

Données **fictives** : **200 Go** à sauvegarder ; **3 Go** de données modifiées par jour ; **rétention de 4 semaines** (28 jours) ; débit de restauration de **100 Mo/s**.

| Stratégie | Description |
|---|---|
| **1** | Une sauvegarde **complète** chaque jour |
| **2** | Une complète le dimanche, puis une **incrémentale** chaque jour |
| **3** | Une complète le dimanche, puis une **différentielle** chaque jour |

Complète (pour les stratégies 2 et 3, une semaine = 1 complète + 6 sauvegardes quotidiennes) :

| | Stratégie 1 | Stratégie 2 | Stratégie 3 |
|---|---|---|---|
| Espace total sur 28 jours | | | |
| Supports à restaurer **au pire** (samedi) | | | |
| Volume à restaurer **au pire** | | | |
| Temps de restauration du volume (100 Mo/s) | | | |

**J'anticipe.** Quelle stratégie prends-tu pour le Cabinet Delorme (budget limité, RTO de 4 heures) ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

| | Stratégie 1 | Stratégie 2 | Stratégie 3 |
|---|---|---|---|
| Espace sur 28 jours | 28 × 200 = **5 600 Go** | 4 × 200 + 24 × 3 = **872 Go** | 4 × 200 + 4 × (3+6+9+12+15+18) = 800 + 252 = **1 052 Go** |
| Au pire (samedi) | 1 copie | complète + **6** incrémentales | complète + **1** différentielle |
| Volume à restaurer | 200 Go | 200 + 6 × 3 = **218 Go** | 200 + 18 = **218 Go** |
| Temps (100 Mo/s) | 200 000 Mo ÷ 100 = 2 000 s ≈ **33 min** | 218 000 ÷ 100 = 2 180 s ≈ **36 min** | idem ≈ **36 min** |

Le temps de transfert seul est bien sous les 4 heures de RTO ; il faut y ajouter la **réinstallation**, la **vérification** et la **communication**. La **stratégie 2** est la plus économe en espace (872 Go) ; la **stratégie 3** simplifie la restauration (deux supports au lieu de sept) pour un espace modéré (1 052 Go) : bon compromis si l'on craint la perte d'un maillon de la chaîne. La stratégie 1 est la plus simple mais la plus coûteuse (5 600 Go).

</details>

**Je comprends.** Pourquoi la stratégie incrémentale est-elle plus fragile à la restauration ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

La restauration suppose la complète **et toutes les incrémentales** dans l'ordre : **un seul maillon manquant** ou corrompu rend la suite inutilisable. D'où l'importance de **vérifier** les sauvegardes.

</details>

## Partie C – Mettre en œuvre et simuler un sinistre (≈ 55 min)

**But :** réaliser une sauvegarde complète puis incrémentale, détruire les données, restaurer et **mesurer**.

### C1 – Préparer les données

```bash
mkdir -p ~/tp-s05/srv/donnees ~/tp-s05/backup ~/tp-s05/restauration
cd ~/tp-s05
for i in $(seq 1 200); do echo "document $i" > srv/donnees/doc$i.txt; done
ls srv/donnees | wc -l
```

**Point de contrôle :** la commande affiche `200`.

### C2 – Sauvegarde complète

```bash
tar --listed-incremental=backup/suivi.snar -czf backup/complete.tar.gz srv/donnees
ls -l backup
```

**Je comprends.** Que contient le fichier `suivi.snar` ? À quoi sert-il ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

C'est le **fichier de suivi** de `tar` : il mémorise l'**état des fichiers** au moment de la sauvegarde. À la sauvegarde suivante, `tar` le compare à l'état actuel et ne copie que ce qui a **changé** : c'est ce qui rend la sauvegarde **incrémentale**.

</details>

### C3 – Faire vivre les données, puis sauvegarde incrémentale

```bash
echo "modifie" >> srv/donnees/doc5.txt
echo "nouveau" > srv/donnees/doc201.txt
rm srv/donnees/doc7.txt
tar --listed-incremental=backup/suivi.snar -czf backup/incr1.tar.gz srv/donnees
tar tzf backup/incr1.tar.gz
```

**J'anticipe.** Quels fichiers vas-tu voir dans la liste de l'incrémentale ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

Le dossier `srv/donnees/`, `doc201.txt` (nouveau) et `doc5.txt` (modifié). La **suppression** de `doc7.txt` est mémorisée dans l'archive (elle sera appliquée à la restauration), mais le fichier n'y figure pas.

</details>

### C4 – Mémoriser l'état attendu, puis simuler le sinistre

```bash
sha256sum srv/donnees/* | sort -k2 > attendu.sha
date +%H:%M:%S               # note l'heure : c'est l'heure du sinistre
rm -rf srv/donnees           # le sinistre
ls srv
```

**Je comprends.** À quoi sert `attendu.sha` ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

À **prouver** que la restauration est **fidèle** : on comparera l'empreinte (SHA-256) de chaque fichier restauré avec celle du fichier d'origine.

</details>

### C5 – Restaurer et mesurer le temps

L'ordre compte : **la complète d'abord, puis l'incrémentale**.

```bash
time ( tar --listed-incremental=/dev/null -xzf backup/complete.tar.gz -C restauration && \
       tar --listed-incremental=/dev/null -xzf backup/incr1.tar.gz -C restauration )
```

Note le temps `real` : ______________

### C6 – Vérifier la restauration

```bash
ls restauration/srv/donnees | wc -l                  # nombre de fichiers
ls restauration/srv/donnees/doc7.txt                 # doit être absent
cat restauration/srv/donnees/doc5.txt                # doit contenir « modifie »
( cd restauration && sha256sum srv/donnees/* | sort -k2 ) | diff - attendu.sha && echo IDENTIQUE
```

**Point de contrôle :** 200 fichiers (200 d'origine − 1 supprimé + 1 nouveau), `doc7.txt` absent, `doc5.txt` modifié, et la mention `IDENTIQUE`.

**Je comprends.** Que se serait-il passé si on avait restauré **l'incrémentale seule** ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

On n'aurait récupéré que **deux fichiers** (`doc5.txt` modifié et `doc201.txt` nouveau) : l'incrémentale ne contient que les **différences**. Sans la complète, les 198 autres fichiers seraient perdus.

</details>

## Partie D – Calculer le RPO et le RTO réels (≈ 15 min)

À partir de tes mesures :

| Grandeur | Valeur |
|---|---|
| Heure de la **dernière sauvegarde** (incrémentale) | |
| Heure du **sinistre** | |
| **Données perdues** si le sinistre avait eu lieu à cette heure (RPO réel) | |
| **Temps de restauration** mesuré (RTO technique) | |
| Temps à ajouter dans un cas réel (réinstallation, vérification, information) | |

**Je comprends.** Ton RPO réel respecte-t-il l'objectif de 4 heures fixé en partie A ? Que faudrait-il changer s'il ne le respectait pas ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

Il dépend de la **fréquence** à laquelle tu lances la sauvegarde : si elle n'est lancée qu'une fois par jour, le RPO réel est de **24 heures** : **non conforme** à un objectif de 4 heures. Il faut **automatiser** la sauvegarde (tâche planifiée) à une fréquence adaptée (par exemple toutes les 4 heures), et **vérifier** ensuite le nombre de supports à restaurer.

</details>

## Partie E – Fiche de reprise et règle 3-2-1 (≈ 15 min)

**1.** Les copies de ton TP respectent-elles la règle 3-2-1 ? Complète :

| Critère | Dans le TP | Pour le Cabinet Delorme, il faudrait |
|---|---|---|
| 3 copies | | |
| 2 supports différents | | |
| 1 copie hors site | | |
| Copie hors ligne ou non modifiable | | |

**2.** Rédige en **dix lignes** la **fiche de reprise** du serveur de fichiers : déclencheur, responsable, ordre des actions (de la décision à la vérification), contacts, test de vérification.

**3.** Ajoute à la fiche une rubrique **« Mode dégradé »** : pendant la restauration, le cabinet doit continuer à recevoir des clients. Réponds aux cinq questions du cours (§5) : fonctions maintenues, capacité, qui décide, durée maximale, retour au nominal.

<details markdown="1">
<summary>Éléments de réponse</summary>

1. **Dans le TP :** une seule copie (les archives sont sur la même machine que les données), un seul support, aucune copie hors site. **Pour le cabinet :** les données de travail + une copie sur un **NAS** local + une copie **hors site** (stockage en ligne chiffré, ou disque stocké ailleurs et renouvelé), dont une copie **non modifiable** ou **hors ligne**.
2. Éléments attendus : constat de panne et **déclenchement** par le responsable ; **information** des utilisateurs ; localisation de la **dernière sauvegarde saine** ; **restauration** dans l'ordre (complète puis incrémentales) sur le matériel de remplacement ; **vérification** (fichiers de test, droits d'accès) ; **retour à la normale** et **compte rendu** ; coordonnées du prestataire, du fournisseur d'accès, de la direction.
3. Mode dégradé attendu, par exemple : consultation des dossiers à partir de la **dernière copie en lecture seule** (poste de secours ou NAS), nouveaux éléments notés sur **fiche papier** ressaisie après reprise ; décision par le responsable dès l'arrêt constaté ; durée maximale cohérente avec le RTO ; retour au nominal après vérification des fichiers et **ressaisie contrôlée**.

</details>

## Pour aller plus loin

- Planifie la sauvegarde avec **cron** (par exemple toutes les 4 heures) et ajoute une **rotation** qui supprime les archives de plus de 28 jours.
- Teste la **perte d'un maillon** : supprime `incr1.tar.gz`, restaure, et décris ce qui est perdu.
